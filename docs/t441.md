# Developer decision attribution and round-cap holds

Status lists recent developer-token events with their recorded actor and acting model. It uses the same event formatter as show, including quoted words when present. The list covers the events returned by the server, not the whole project history. Older events without a recorded model cannot identify one retrospectively.

A round-cap hold requires the developer actor, nonblank quoted words and the acting model before unblocking. The ledger checks this before changing state, clearing a pre-review fence or recording an unblock event. Existing round-cap holds are recognised by the orchestrator actor and the recorded round-cap reason, so no migration or new identity is needed.

## Callers and compatibility

- CLI unblock calls POST /api/projects/:project/items/:id/unblock. Its existing --quote and --as flags supply the direction. No request shape changed.
- The API checks authentication and project access before dispatch. An agent token is bound to its actor and project grants; it cannot supply the developer direction. The developer token must identify its acting model. Ordinary blocks still allow the holder or developer; round-cap holds additionally require the developer direction. There is no separate membership or edit-right model on this operation.
- The signed-in task page calls Ledger.unblock as the developer without direction. It can still clear ordinary blocks, but a round-cap refusal now directs the developer to the quoted CLI command. No generated page or form changed.
- The runner and CLI callers use the same endpoint. Timeout facts and pre-review retries retain their existing checks. Existing tests cover these paths.
- show already reads acting-model events. Status project text, project JSON, all-project text and all-project JSON now include the same attribution. No additional endpoint or permission is introduced; status uses the project events it already reads.
- Direct ledger tests use the existing direction argument for the round-cap success case. Other unblock callers remain compatible for ordinary blocks.

## Disclosure

This change introduces no visibility level or caller-selected disclosure parameter. Authenticated project access continues to govern project responses and their events. Unauthorised callers receive the existing refusal. Status and show print only returned event attribution. Search snippets, exports, derived data, browser copy and generated pages gain no new fields or rendering. No browser visual change is made.
