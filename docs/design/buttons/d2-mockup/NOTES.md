# d2 mockups: Answer and Override on the task page

These are built from the chosen task page (bakeoff-task-page/work/opus/task.html). Its CSS is in `mock.css`, plus the d2 forms. `theme.css` is a byte-identical copy of `~/ai-projects/atelier/src/theme.css` at b91b451d. The fonts come from the same Google Fonts URL the site serves (`src/ui.ts:188`). Run `python3 -I build.py` to write the HTML, then `node render.mjs` to write `shots/`: 3 states x 1280/390 x light/dark, full page. The render measured scrollWidth at 390 as 390 for every state, so nothing scrolls sideways.

The colours are theme variables only, with no colour literals. Everything in the pages is invented: task ids, titles, heads, times, questions, findings and summaries. The only models named are claude-code/sonnet-5.5 and codex/gpt-6-astra.

## Found while building
- **Override on a sent-back task is not offered on main.** The page offers the override only when `gate.needsAssessor && gate.blockers.length === 1` (`src/ui.ts:2481`). Today's call `override` is "No reviewer", the case where no qualifying reviewer exists. `reviewOverrideFor` (`src/rules.ts:1664-1678`) *can* waive agent rejections at the head (`rejectionsOnly`), but no form offers that for a plain rejection. State C draws what the brief asked for, so it shows a case main's page would not show. See open call 1.
- The bake-off shots (B-*.png) used fallback system fonts because that brief allowed no web fonts. These shots load Plex and Bricolage as the site does, so the type looks slightly different from the shots PAVI picked from.

## Open design calls
1. **Is Override offered on a sent-back revision?** (a) Only where the independent review is missing or no reviewer qualifies, as on main and in the d2 criteria. State C would then be a protected change with no qualifying reviewer, and the "This overrides…" box would name the missing review instead. (b) Also for a rejection at the shown head, which `reviewOverrideFor` already supports. **Recommend (a)** for d2: it matches main and the drafted criteria. Offering an override of a rejection is a policy change that needs its own decision from PAVI.
2. **The gold primary button in light.** (a) Tokens only, as shown: the theme's pale gold (`--signal-deep-rgb`) with dark gold text. It is lighter than the chosen mockup's Land, which used Night's gold `#ffd166` as a literal. (b) Add one theme token, such as `--signal-fill`, so Land and Send answer share Night's gold in both schemes. **Recommend (b)**: Land and Send answer should look like one family. Because `src/theme.css` is a copy made by `bin/sync-theme`, the token has to be added at its source.
3. **Where the form sits in the verdict card.** (a) Between the verdict sentence and the track, as shown, so the action stays with its verdict as task c's order says. (b) Below the track, so the card's top half reads the same in every state. **Recommend (a)**. In C the open disclosure pushes the track well down the page, and (b) would avoid that, but the order is decided.
4. **Unblock on a fact block: outline or primary.** (a) Outline, as shown, since gold means waiting on you and a fact block does not. (b) Primary, as main draws it. **Recommend (a).**
