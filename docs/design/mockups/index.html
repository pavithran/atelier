Conventions

  • Frames. Each page shows a desktop frame drawn at 1440 CSS px and scaled down with zoom (0.55, or 0.42 for smaller variants), beside a phone frame drawn at 390 px at full size. They sit side by side and wrap on narrow screens; the desktop frame scrolls sideways inside itself if it does not fit. A caption above each frame names the width and route.
  • Numbering. Yellow numbered circles in a frame mark a change; each links to the note of the same number under the frames. A note says what changed and cites the finding and proposal, written "F3 → P3". Markers are not part of the design.
  • Navigation. Every owner page draws the two-row owner bar of plan.md §2 — row 1: Atelier, Decisions (14), Projects, Activity, project switcher ▾, Pavi ▾; row 2 under a project: "Ledger Core › …", Overview, Tasks (200), Code, Activity, Settings — with one aria-current per row. Phones use "Atelier · Decisions (14) · Menu ▾", a location line and a tab strip that scrolls sideways. Visitors only ever get the public bar.
  • States. Task states use only the words of brief §5, each as a tag coloured by role with a shape, so colour never carries a state alone: Ready to startWorkingWorking · stale 2 dReady to acceptNeeds reviewSent backChecks failedReady to mergeBlockedMergedClosed Non-task statuses (a model, a runner, a project) use the same roles with their own plain words.
  • Tokens. mockup.css copies the Night (dark, default) and light (prefers-color-scheme: light) values from src/theme.css and the five family colours from src/layout.css. Text uses role tokens only, which pass 4.5:1 in both schemes; family colours appear as swatches, stripes and graph lines, never as small text. Focus is a 2 px --signal-hot ring on every focusable element.
  • No script, no requests. Static HTML and one stylesheet; fonts are named with system fallbacks only; no images, no web fonts, no script. Menus are closed <details>; forms do nothing.
  • Landmarks. Each frame stands for a separate page and so has its own header, labelled navs, main and one h1. A mockup file therefore holds several main elements, which a validator flags; the shipped pages have one each.
