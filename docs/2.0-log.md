## Task 1: the server runs under Node with SQLite Ledgers (t396)

Built by claude-code/opus-5.5 on 2026-10-28, branch `2.0/t1-node-runtime`.

**What.** `cli/serve.mjs` runs one process per environment and serves `src/index.ts`'s `fetch` over Node's `http` (`src/runtime/server.mjs`). Module hooks load the Workers sources unchanged (`src/runtime/loader.mjs`). Each Ledger Durable Object is a SQLite file of its own under `DATA/ledgers` (`node:sqlite`, mode 600), with:
- a queue per object, so calls never interleave;
- one transaction per call;
- savepoints for `transactionSync`;
- structured clones across the stub;
- errors crossing as plain Errors;
- alarms kept in the object's own file and delivered at least once (`src/runtime/namespace.mjs`).

Artifacts, R2 and the landing Workflow refuse with `not_supported` until later tasks. The 132 Workers test files are skipped by name (`test/workers-skipped.txt`); `ATELIER_WORKERS_TESTS=1` still runs them in workerd.

**Decisions taken while building.**
- **One SQLite file per Durable Object name**, not one file per environment as the design said. The Ledger's SQL, dump and import stay unchanged, and no table names need prefixing.
- **`node:sqlite`** (built into Node 26) instead of `better-sqlite3`: no native build.
- **Every call commits, thrown or not**, as the Workers runtime keeps writes made before a throw outside `transactionSync`.

**Criteria.**
1. `serve` answers `/api/version`, and `atelier login`, `new`, `ls`, `show`, `edit` and `decide` work against it: `test/node-server.test.mjs`, first test.
2. Node test files pass, with `src/rules.ts` and `test/rules.test.ts` unchanged and the Workers tests skipped by name. Full run on the merged head 527d864a (both pieces): 4,505 pass, 0 fail, 3 skipped as before, and 132 Workers files skipped by name; typecheck clean.
3. Calls to one Ledger never interleave, and concurrent creates on the real Ledger stay ordered. An alarm fires within a second, the real Ledger's included, after a restart too: `test/node-server.test.mjs`.
4. The data directory is mode 700 and every file in it 600. No file holds the owner token, the override secret or a minted agent token: `test/node-server.test.mjs`.

**Review.** codex/gpt-6-astra, four rounds.
- **Round 1, reject.**
  1. *A BigInt fallback re-ran writes:* fixed; every statement reads BigInts.
  2. *An alarm was deleted before its handler committed:* fixed.
  3. *`scheduled()` is not on timers:* refuted, because the plan gives it to task 8; astra accepted that in round 2.
  4. *Arguments were cloned late:* fixed.
  5. *Tests:* added for the real Ledger's alarm, retries and savepoints.
- **Round 2, reject.** A replacement alarm for the same moment was lost, and alarm changes escaped the handler's transaction. Fixed by moving each alarm into the object's own file (`_atelier_alarm`, which the dump skips), with a generation, written in the call's transaction. Tests added for each case.
- **Round 3, reject.** Rolling back a savepoint restored the alarm row but not its timer. Fixed: the timer is set again from the row after every call settles and after every rollback. Test added.
- **Round 4, approve** (about 12:25 pm), no findings.

### G10, retries in the CLI

Built by claude-code/sonnet-5.5, with fixes by claude-code/opus-5.5; branch `2.0/g10-retry`.
- **What.** `request()` retries three times (1, 2 and 4 seconds) only:
  - reads;
  - pushes, idempotent by head;
  - writes that provably never left: connection refused, DNS or no route on the original URL, with redirects not followed on writes.

  Any other uncertain write stops with "may have applied: run ...". That doubt survives later refusals.
- **Commands safe to rerun by hand.** submit, review-withdraw, undispatch, abandon, release and approve answer "already" and exit 0. Each "already" is bound to what the command named and given only after the request's own validation; a release records who released (`by`).
- **Review.** codex/gpt-6-astra, four rounds.
  - Round 1 rejected the first design, a server-side cache of idempotency keys: it stored plaintext credentials and could not prove exactly-once. That design was removed.
  - Round 2 rejected automatic retries of writes, which were not bound to their target. The retries were narrowed to the three cases above.
  - Round 3 found doubt lost on two exits, and a repeated release that skipped its note check. Both fixed.
  - Round 4, approve.

### G7, the check limit is a project setting and counts from the held slot

Built by claude-code/opus-5.5, branch `2.0/g7-check-limit`.
- **Policy.** `atelier init --check-limit MINUTES --silence-limit MINUTES --startup-limit MINUTES --slot-wait-limit MINUTES --check-silence CMD=MINUTES` records `checkLimitMinutes` (the hard ceiling, default 60 since e7044f32), `silenceLimitMinutes` (default 10), `startupLimitMinutes` (none by default), `slotWaitLimitMinutes` (default 60) and a check's own silence. `atelier check`, a landing (its checks and regenerate), `wrap`, a runner's clean-clone run and the builder's brief (from the job brief) read them from the server; `ATELIER_CHECK_TIMEOUT` is gone. `show` prints the limit; there is no situation read yet.
- **Clock** (`cli/check-clock.mjs`). The slot wrapper reports the held slot on a descriptor, and every limit counts from there. A run is silent when it prints nothing, its process tree spends no CPU and starts or ends nothing, and no child process is alive; a run that printed nothing, showed no child and spent no CPU time within the startup limit is stopped as "showed no work in N minutes" (a child that starts and ends between two readings is not seen, so the words name what was observed). A run that waits past the slot-wait limit is stopped as "waited N minutes for a test slot".
- **Reporting.** A stopped run prints `STOP`, posts `stopped: {kind, minutes}` with its evidence, is not rerun as a flake, and `show`, `done --json` (outcome `stopped_checks`) and `wrap` say what stopped it, never a failed test.
- **Blocks.** A validation_blocked release whose reason starts with those words, or whose newest observed check was stopped, is blocked with `fact: "timeout"`. Any model lifts it with `atelier unblock`, without the developer's words; both events record the fact.
- **Not done.** Harness runs (the builder's own process) do not use the clock yet.

## Task 5: claim makes a branch; the CLI and runners clone and push one branch (t400)

Built by claude-code/opus-5.5, branch `2.0/t5-claim-branch`.

**What.**
- **Claim.** On the Node server, a claim creates `refs/heads/t/N` at the project branch's tip, records the base, and mints the task grant as the item's write token. Its answer carries the remote, the branch, the base, the token and the prose standard's text. No Artifacts call is made.
- **CLI.** It clones `--single-branch --branch t/N` with one remote and pushes `HEAD:refs/heads/t/N`. Check, diff and review clones read through read grants.
- **Runners** do the same, and `git-token` is in `RUNNER_ROUTES`.
- **Init** creates the bare repository; the owner pushes with the server token.
- **The tailnet's plain `http://`** (100.64.0.0/10) is accepted.
- **The advertised remote** comes from the address the server accepted the connection on, or the configured `PUBLIC_ORIGIN`, never the caller's Host or request target.

**Write isolation, as hardened by review.**
- `git-token` for a runner needs its own job on the task; an agent gets a grant only for its own actor.
- Closing a task clears its write token in the same write, and the host refuses a grant for a closed task or a former holder.
- The hook re-checks the grant at push time over a loopback-only internal listener with a per-process secret.
- One lock per task, and one per project for multi-task changes, serializes every push with every change that ends or rotates a grant. Every Ledger stub call goes through one lock table, `src/runtime/ledger-locks.mjs`. A test scans `src/ledger.ts`, following calls transitively, and fails if a method that writes `owner`, `token_id` or `claim_gen` is missing from that table.

**Review.** codex/gpt-6-astra, six rounds.
1. Reject: a runner could take another holder's grant, and grants survived a merge.
2. Reject: a push already in flight survived revocation, and the remote could be steered by the request target.
3. Reject: a window remained between the grant check and the ref update, and a non-loopback bind broke pushes.
4. Reject: a timed-out waiter broke exclusion, the browser actions bypassed the lock, and a disconnect while queued was missed.
5. Reject: the coverage scan missed public callers, and an aborted acquisition leaked a slot.
6. Approve.

**Full suite** on the branch after merging the 2.0 branch in: 4,676 pass, 0 fail, 3 skipped.

**Left.** Plan and part branches (`plan/N`) are coded but untested. The refresh lease, the owner-port token and a write `baseline-token` still go through Artifacts or return no token.

### G1 and G2, a landing as a readable fact that keeps the reviewed head

Built by claude-code/opus-5.5, branch `2.0/g1g2-landing`.

**What.** The landing order is now:
1. **Before the lease:** preflight and the moved-code comparison. A claimed task is checked and submitted at its recorded head. Then triage, the review and the gate.
2. **Under the landing lease and the checkout lease:** accept, then `atelier merge ID --landing` in the registered checkout. It merges, folds regenerate into the merge commit, runs the checks once on the merged tree, pushes the merge to the project branch, pushes the notes and records the merge.

No push goes to `t/N`, so the approvals for the reviewed head stand.

**Guards on that order:**
- The checkout must be exactly at the fetched project tip, and so must any unfinished merge journal it resumes.
- The merge clone must stay at the merge commit with no tracked or staged change before and after each check.
- Main moving between checks and push is redone at most twice, then reported as a fact.

**Landing records.** Each step is recorded with its attempt, and a failure with the failing step's tail, readable by `show --json`.
- `land tN --queue --cancel` withdraws a queued landing; a cancel is refused once the merge has begun.
- A failure stops automatic retries until the model acts or the head changes.
- The attempt passes to the merge child explicitly, and a stale attempt cannot record against a newer one.
- The hook lets owner and landing credentials push `refs/notes/atelier`.

**Review.** codex/gpt-6-astra, nine rounds. Each round narrowed:

2. A resumed journal skipping the tip check, and merge entry without the lease.
3. A refused entry still recording a failure.
4. Failure recording made too strict: lapsed leases, pre-lease steps, interrupts.
5. The fallback adopting another attempt, and a triage stop marked recorded too early.
6. The merge child adopting a newer attempt.
7. A manual `--landing` with no attempt.
8. The attempt check after an `--approve` write.
9. Approve.

**Merged with G9.** The landing holds the checkout lease through its merge. A hand commit in the checkout is refused as unreviewed, which is G9's fact for a changed checkout head and stops it from being published. Full suite on the branch after merging: 4,681 pass, 0 fail.

- **Runners and `git-token`.** Runners cannot call `git-token` yet; their route inventory (`RUNNER_ROUTES`, `src/tokens.ts`) and the runner test server need it. Task 5.
- **Repositories at init.** A repository is created on first authorised Git access. `atelier init` still calls `ARTIFACTS.create` and mints an Artifacts baseline token. Tasks 5 and 11.
- **The landing-grant route.** The grant store already mints landing grants; the route that gives them to the lease holder is task 6.
- **Crons.** `worker.scheduled()` (stage tick, stuck episodes, model snapshots) has no timer yet. Task 8.

It reads the builder's stream-json log and the task branch, and belongs with G4's situation read. The stall and startup rules go into G7.
